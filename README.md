Next.js App Router demo of a full-screen scribble overlay on route change, driven by [`next-transition-router`](https://github.com/ismamz/next-transition-router). The same overlay is implemented twice: once with [Motion](https://motion.dev/) and once with [GSAP DrawSVG](https://gsap.com/docs/v3/Plugins/DrawSVGPlugin/).

Click **Test Route** on `/` or `/test` to see it. Use the **Motion / GSAP** toggle in the top-right to compare engines on the same route change. The stroke draws on during leave, then continues in the same direction during enter — it does not rewind.

## Getting started

```bash
bun install
bun dev
```

Open [http://localhost:3000](http://localhost:3000).

| Script | Command |
| --- | --- |
| Dev | `bun dev` |
| Production build | `bun run build` |
| Start | `bun start` |
| Lint | `bun run lint` |

Requires [Bun](https://bun.sh/).

## How the overlay works

[`TransitionRouter`](https://github.com/ismamz/next-transition-router) wraps the app and runs `leave` before the URL changes, then `enter` after the new page is ready. Use its `Link` instead of `next/link` so those callbacks fire.

| Phase | Sequence |
| --- | --- |
| **Leave** (~1.2s) | Overlay visible → black scrim fades in (0.2s) → blue scribble draws and thickens (1s) → `next()` |
| **Enter** (~1s) | Scribble continues forward and thins (1s) while the scrim fades out (0.25s, in parallel) → overlay hidden → `next()` |

The SVG path, stroke widths (`1%` → `31%` → `1%`), and overlay CSS live in `app/globals.css` and are shared by both providers.

## Switching between Motion and GSAP

`providers/index.tsx` wraps the app (imported as `@/providers` in `app/layout.tsx`) and exposes a Motion / GSAP toggle. Changing the engine remounts the matching provider so the next route change uses that overlay.

| File | Engine | Draw technique |
| --- | --- | --- |
| `providers/providersMotion.tsx` | Motion `useAnimationControls` | `pathLength` + `pathOffset` (DrawSVG wrap equivalent) |
| `providers/providersGSAP.tsx` | GSAP + DrawSVGPlugin | `drawSVG: "0%" → "100%"` then `"-100%" → "0%"` |

GSAP is the visual reference. Motion maps the same timing, easing (quadratic / `power1`), and same-direction follow-through.

## Project layout

```
app/
  layout.tsx              # Root layout; wraps children in Providers (`@/providers`)
  page.tsx                # Home (`/`)
  test/page.tsx           # Second route (`/test`)
  globals.css             # Overlay positioning, scrim, scribble color
providers/
  index.tsx               # Motion / GSAP toggle and engine switch
  providersMotion.tsx     # Motion overlay implementation
  providersGSAP.tsx       # GSAP overlay implementation
```

Routes are placeholders so you can trigger the transition. The interesting code is the two providers.

## Stack

- Next.js 16 (App Router) + React 19
- TypeScript
- Tailwind CSS 4
- [`next-transition-router`](https://github.com/ismamz/next-transition-router)
- Motion and GSAP (DrawSVGPlugin)

This repo includes `AGENTS.md` for agent tooling. Next.js 16 APIs can differ from older docs — read `node_modules/next/dist/docs/` before changing framework code.
